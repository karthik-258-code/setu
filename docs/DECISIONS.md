# Decisions (ADR-lite)

One line per decision. Newest at the bottom. Agents append here when they resolve an ambiguity; humans append here when they change direction.

Format: `- YYYY-MM-DD [task] Decision. Reason.`

- 2026-10-26 [foundation] Monorepo with pnpm workspaces: `packages/engine`, `packages/content`, `packages/shared`, `apps/web`, `apps/api`. One language (TypeScript) across engine, web and API so the engine runs unchanged offline and on the server.
- 2026-10-26 [foundation] Student state is event-sourced: `StudentState = replay(pack, events)`. Sync is an idempotent append of events. Removes any possibility of offline/online estimate drift and makes paper entry and teacher actions ordinary events.
- 2026-10-26 [foundation] Engine is pure and deterministic (`now` and seeded `rng` are parameters). Required for golden-vector tests shared by browser and server, and for reproducible simulations.
- 2026-10-26 [foundation] Engine returns `ruleId + reasonParams`; bilingual reason text lives in the content pack. Keeps the engine free of user-facing strings and makes adding a language a content change.
- 2026-10-26 [foundation] Content is versioned JSON in the repository and is **not** stored in PostgreSQL in v0.1. Packs are static files. Fewer tables, simpler sync, and the same files serve demo mode.
- 2026-10-26 [foundation] Readiness Check asks **one** question per direct prerequisite first, then descends on failures, then confirms with second questions. The submission's "two per prerequisite" would exceed the 12-item budget for chapters with 7 external prerequisites.
- 2026-10-26 [foundation] Demo mode (`LocalDemoApiClient`) runs the full teacher and student experience in the browser over a seeded classroom. The Prove-round demo must not depend on the API or network.
- 2026-10-26 [foundation] Simulation is written in TypeScript against the real engine (`pnpm sim`); Python/pyBKT fitting is Phase 7 stretch. Same code under evaluation as in production.
- 2026-10-26 [foundation] Graph spans Classes 6 to 10 on the algebra spine with one full-depth chapter (Class 8 LEQ) and three skeleton chapters (Class 7, 9, 10). Answers the evaluator's scalability ask within the Build-round budget.
- 2026-10-26 [foundation] GitHub is the final home. `.github/workflows/ci.yml` is canonical; `.gitlab-ci.yml` mirrors it while hosted on GitLab. Push mirroring from GitLab to GitHub keeps both in sync during the event.
- 2026-10-26 [foundation] Student PII limited to `firstName`, `rollNo`, `classroomId`, `lang`, `pinHash`, as in the submission's DPDP Act analysis.
- 2026-10-27 [0.1] Web router is React Router (v6, data-router API not required). Smaller learning surface than TanStack Router, and route-level lazy loading is enough to hold the 1 MB gzipped budget.
- 2026-10-27 [0.1] ESLint 9 flat config at the repo root (`eslint.config.js`: `@eslint/js`, `typescript-eslint` recommended, `eslint-plugin-react-hooks`, `eslint-config-prettier`) and Prettier (`.prettierrc.json`, `pnpm format`). Each package defines `lint` as `eslint .` and inherits the root config; existing files are not reformatted in this task.
- 2026-10-27 [0.1] `content:validate` and `content:pack` go through `scripts/run-if-present.mjs`, which prints a message and exits 0 while `packages/content` does not exist (until 0.3). `build` already exits 0 because `pnpm -r build` skips packages without a `build` script. Lets CI stay green before the content package lands.
- 2026-10-27 [0.2] `pnpm sim` runs `packages/engine/scripts/sim.mjs`, a dependency-free Node placeholder outside `src/` (so the engine stays pure) that prints usage and exits 0 until 6.2; `--passWithNoTests` was dropped from the engine `test` script so an empty suite fails. Simplest option; no tsx needed yet.
- 2026-10-27 [0.3] Cycle detection lives in the engine: `graph.ts` gains `buildGraph` (Kahn topo order, tie-break `classLevel` then `id`, unknown prerequisites ignored) and `assertDag` (throws naming one concrete cycle), with engine unit tests; the rest of 1.1 is untouched. The content validator calls them, so there is one graph implementation (AGENTS "one engine everywhere").
- 2026-10-27 [0.3] Content TS scripts run through `tsx` (devDependency of `@setu/content`) with no build step, invoked as `node --import tsx` rather than the `tsx` CLI because the CLI's IPC socket fails in restricted sandboxes. Zod 3 is used, and schemas are wrapped in a compile-time `mirror<EngineType>()` check so drift from `types.ts` fails typecheck; objects are `.strict()` so typos in content JSON are errors.
- 2026-10-27 [0.3] Root `content:validate` and `content:pack` now call `pnpm --filter @setu/content run <script>` directly and `scripts/run-if-present.mjs` is deleted, since the package exists. `run` is explicit because bare `pnpm pack` is a built-in command. Empty `questions/`, `templates/` and `resources/` folders are kept with `.gitkeep`; `pack` prints "0 packs built" and exits 1 if chapters exist until 2.7 implements writing, rather than silently writing nothing.
- 2026-10-27 [0.4] `POST /sync` responds `{ accepted, rejected: [{ id, reason }], serverTime }` and the `ApiClient.sync` signature in ARCHITECTURE 7.4 and 8.1 is updated to match, since 8.2 requires rejected events to be returned with reasons. Event schemas cap a batch at 200 (`MAX_SYNC_EVENTS`) and are `.strict()`, so unknown fields and event types are rejected.
- 2026-10-27 [0.4] `@setu/shared` has its own `mirror<T>()` that checks assignability in both directions (the content one is one-way), because events cross the network and an extra or missing field must fail typecheck. Content schemas (`conceptSchema`, `questionSchema`, ...) are reused from `@setu/content` unchanged; its index already exports them, so no change there. `StudentState`, `ContentPack`, `GapMap`, `GapGroup` and `WeeklyView` are deep-validated and drift-checked, none was cut to top level.
- 2026-10-27 [0.4] Endpoint DTOs not fixed by types.ts: teacher login returns `{ accessToken, refreshToken }`; student login returns `{ accessToken, student: { studentId, firstName, rollNo, classroomId, lang } }` (no `pinHash`) with a 4-digit PIN; refresh takes `{ refreshToken }` and returns a new pair; `GET /classrooms` returns `{ id, classLevel, section, code, launchedChapters[{ chapterId, trimmed, launchedAt }] }[]`; launch returns the launched-chapter entry; `POST /classrooms/:id/events` returns `{ id, serverTime }`; `/health` returns `{ status: "ok" }`. Simplest shapes consistent with 8.1 and 8.3.
- 2026-10-27 [0.4] `ApiClient` gains `getMyState`, `getClassrooms` and `launchChapter` for the 8.1 endpoints that 7.4 omitted; `sync` stays `sync(events)` with the device id bound at client construction. `@setu/shared` also exports `routes` (Fastify patterns) alongside `paths` (URL builders) so the API registers the same strings the web calls. Timestamps are validated as ISO-8601 datetimes (`offset: true`), so clients must send `toISOString()` style values.
- 2026-10-27 [0.5] Router is React Router v6 using the data-router API (`createBrowserRouter`), with the `/s/*` and `/t/*` groups loaded through route `lazy()` into separate chunks. Supersedes the 0.1 note that the data-router API was not required; the task brief asks for it and `lazy` is what keeps student and teacher code split.
- 2026-10-27 [0.5] Tailwind CSS v3.4 (PostCSS plugin plus `tailwind.config.ts`), not v4. Stable, widely documented, and v4's Rust/Lightning CSS tooling adds sandbox and browser-support risk for Android WebView. Mobile-first: unprefixed utilities target 360 px; the shell caps width at `max-w-3xl`.
- 2026-10-27 [0.5] ARCHITECTURE 7.1 lists Zustand, but 0.5 permits only react, react-dom, react-router-dom, dexie and the workspace packages, so Zustand is not added. Language state uses React context; add Zustand later only with its own entry if a task needs it.
- 2026-10-27 [0.5] UI language is `"en" | "te"` (`UiLang`) although `Lang` also has `hi`; Hindi is not in v0.1 scope. `t()` returns `{ text, fallback }`, a blank Telugu string counts as missing, and `<L>` appends the "English only" marker on fallback. UI chrome uses `ui(key)` over `strings.ts`; the Telugu there is plain-language and should get a native-speaker review before pilot.
- 2026-10-27 [0.5] `events` is typed as `Table<StoredEvent, string>` rather than `EntityTable`, because `EntityTable`'s insert type is not distributive over the `StudentEvent` union and rejects variant-specific fields. `StoredEvent = StudentEvent & { synced: 0 | 1 }`, `StoredPack` wraps `ContentPack` with `packVersion`, and `meta` values are `unknown`; no data-layer logic until 3.1.
- 2026-10-27 [0.5] PWA: `generateSW`, `registerType: "autoUpdate"`, app shell precached, SPA `navigateFallback` (denying `/packs/` and `/api/`), and a `CacheFirst` runtime rule for `/packs/*.json` in cache `setu-packs`. "Keyed by `packVersion`" is met by the URL: 3.1 must request `/packs/<chapterId>.json?v=<packVersion>` (Workbox keys on the full URL) so a new version is a new entry. Icons are 192 and 512 PNGs generated programmatically (white bridge arch on teal), with the 512 also declared `maskable`. No fonts or CDNs; the font stack is system fonts including Noto Sans Telugu.
- 2026-10-27 [0.5] The 1 MB gzipped JS budget step in `.github/workflows/ci.yml` no longer skips when `apps/web/dist/assets` is missing (the app exists now, so a missing build must fail), and the same step is added to `.gitlab-ci.yml`. Current total is 69,894 bytes gzipped.

- 2026-10-27 [0.6] `/health` returns `{ status: "ok", version }` (version read from `apps/api/package.json`); `healthResponseSchema` in `@setu/shared` gains `version`, superseding the 0.4 note that it returns only `{ status }`. Task brief asks for it. The route never touches the database.
- 2026-10-27 [0.6] Prisma 5.22 (not 6) with ids as `cuid()` strings except `Event.id` and `Device.id`, which are client-generated and have no default (events must keep their client id for idempotent sync). `Student.rollNo` is `String` to match `StudentSummary.rollNo` and the shared DTOs; `Teacher.role`, `Student.lang`, `MasteryState.source`, `Recheck.kind` are plain strings (validated by zod, not Prisma enums) so the engine's unions can grow without migrations; `Classroom.launchedChapters` defaults to `[]`. - 2026-10-27 [0.6] The initial migration was generated offline with `prisma migrate diff --from-empty --to-schema-datamodel` (no database in the sandbox) and `migration_lock.toml` written by hand; it is unverified against a live PostgreSQL until someone runs `prisma migrate deploy`. `prisma generate` runs in `postinstall` and `pretypecheck` so typecheck works in CI without a database.
- 2026-10-27 [0.6] API runs TypeScript through `node --import tsx` (dev, watch mode) with no CLI, and `build` type-checks then bundles `src/server.ts` to `dist/server.js` with esbuild, keeping dependencies (fastify, @prisma/client, zod) external. The bundle inlines the workspace packages (`@setu/shared`, `@setu/engine`), which export raw `.ts` and cannot be loaded by plain `node`; `start` is `node dist/server.js`. Server entry listens on `PORT` (default 3000) and `HOST` (default 0.0.0.0). `@setu/engine` is a declared dependency as the brief requires but is not imported until Phase 4.
- 2026-10-27 [0.6] Unknown routes and handled errors return `{ error: { code, message } }` built through the shared `errorResponseSchema`; 5xx responses hide the underlying message (`INTERNAL_ERROR`). Fastify's own 400s (for example malformed JSON) map to `BAD_REQUEST` and similar codes; zod request validation lands with the endpoints in Phase 4.
- 2026-10-27 [1.1] `rootCauseGap` candidates are touched concepts (a mastery entry exists) with `pKnown < 0.9` in the chapter's ancestor set, which is the ancestors of the chapter's concepts minus the chapter's own concepts. Untouched concepts are never candidates (they only count as "clear" when checking a candidate's prerequisites), otherwise every new student would have a root cause and `ready`/`not_attempted` in 5.6 could not work; chapter concepts are excluded because 5.6 scopes the gap to prerequisites. Unmastered chapter prerequisites that lie inside a cycle-free ancestor set are the only blockers considered.
- 2026-10-27 [1.1] Graph queries take mastery as `Readonly<Record<ConceptId, { pKnown: number }>>` (exported `MasteryView`), which `StudentState.mastery` satisfies, so the engine does not need a full `MasteryState` to ask about the graph. `directPrereqs`, `ancestors`, `descendants` and `chapterExternalPrereqs` return topo order; `frontier` returns lowest `classLevel` then topo order; `frontier` throws on an unknown id in `scope` and all functions throw `Unknown concept id: X` or `Unknown chapter id: X`. Prerequisites pointing to unknown concepts are ignored, consistent with `buildGraph`.
